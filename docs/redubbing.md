# 下载视频后，修正中文配音并按口型节奏剪辑

[返回首页](../README.md) · [安装与命令](usage.md)

本次 Muse 生成的中文口播出现过错词、含糊和语速不自然。两条公开样稿最终都用了本地 TTS2 重配声音：**保留 Muse 的人物画面，用确认的正确稿重新配音，再把短句节奏对齐到原画面。**

![下载、Whisper定位、TTS2重配，以及原声、未对齐配音和最终配音的真实波形对照](guide/04-voice.jpg)

## 这次实际怎么做

1. **下载 Muse 视频，保留原件。** 画面与接点合适后另存本地版本。原声即使念错，仍能提供开口、停顿和收声的大致位置。
2. **Whisper 找时间，波形修正边界。** 用本机 `whisper-cli` 识别原声，得到短语的大致时段；再根据音频波形的有效发声起止修正，结合画面核对。Whisper 识别出的错字不拿来改写用户稿。
3. **TTS2 按正确稿生成新配音。** 白衬衫样稿先试听选中 6 号，再以这份试听音频为参考克隆声音，生成完整稿；小雅最终选择了 10 号声音。6/10 是本次试听编号，不是仓库附带的音色预设。白衬衫有一句还进行了同音色补录，再放回对应位置。
4. **把新配音切成短语，逐句调节奏。** 白衬衫整稿切成了 12 个短语。裁掉多余首尾静音，用 FFmpeg `atempo` 在保留音高的情况下调整每句时长，再把每句移动到原画面对应的发声位置，保留句间停顿。
5. **替换原声音轨，单独编排背景音乐。** 去掉 Muse 原声音轨，避免错词、底噪或原有背景声再次混入。画面保留，加入对齐后的干净人声；需要的配乐随后单独混合。
6. **按最终声音复核字幕与口型。** 再用 `whisper-cli` 辅助定位新配音，字幕文字仍使用确认稿；复核字幕时间、句子起止、停顿，以及画面开口/闭口是否合拍。明显不匹配的句子需要进一步剪辑、重配，或重做画面。

这里的“对口型剪辑”是**把声音的短句起止和节奏贴合现有口型画面**。本次没有用新声音重新驱动嘴部；原画面若说了不同音节，单靠移动和变速不能保证逐字嘴型一致。

## 白衬衫样稿的具体时间

制作记录先在 37.5 秒版本里记录原声发声区间，再让画面与对齐后的声音一起以 1.25 倍速变成 30 秒。下表是**有效发声区间**，不是音频文件起点，也不是字幕显示时长。

| 短语 | 37.5 秒版本的发声区间 | 30 秒成片的对应区间 |
|---|---|---|
| 不想每次做视频 | 1.06–2.36 秒 | 0.848–1.888 秒 |
| 都重新出镜录一遍 | 3.15–4.77 秒 | 2.520–3.816 秒 |
| 这个数字人口播项目 | 6.50–8.15 秒 | 5.200–6.520 秒 |

这也解释了为什么不能把一整条新配音直接放在 0 秒：本片第一句约在 0.85 秒才发声，后续短语之间还有停顿。最初换声版本曾过早起音，后来按发声区间重新对齐。

## 在自己的工程中操作

以下在[命令指南](usage.md)的 `work/demo` 目录运行，输入 `main.mp4` 是已经选好剪点的画面。所有输出使用新文件名；再次运行时换名，保留已有版本。

### 1. 提取原声，让 Whisper 辅助定位

```bash
ffmpeg -n -i main.mp4 -vn -ac 1 -ar 16000 source-16k.wav
whisper-cli -m "$WHISPER_MODEL" -f source-16k.wav -l zh \
  -oj -osrt -of source-asr
```

`source-asr.json` 和 `source-asr.srt` 用来找时间，不作为正确台词。把确认稿、原声波形和画面放在一起检查，记录每句的目标发声起止。若画面计划整体变速，先定最终速度，或对声音和所有时间统一换算；不要混用原速与倍速时间。

### 2. 用自己的 TTS2 生成正确稿并切短句

在你使用的 TTS2 界面或命令行中选择声音，输入**确认的完整台词**，导出新配音。声音克隆使用自己有权使用的参考音频。仓库不内置 TTS2，也没有能通用调用所有 TTS2 封装的生成命令；生成完成后，把真实 WAV 文件带回本工程。

按发声内容切成 `phrase-01.wav`、`phrase-02.wav` 等。可以先生成整稿再切，也可以逐句生成；逐句时保持同一声音参考。检查错词，必要时补录单句，不把有问题的字靠极端变速硬塞进去。

### 3. 填配音计划，再按短句替换

复制[配音计划示例](../examples/voice-plan.json)，为每段音频填入：

- `audio`：真实短句文件，路径相对计划 JSON。
- `rate`：播放速度倍率，当前支持 0.5–2；大于 1 加快，小于 1 放慢。起始估算为“新语音有效发声时长 ÷ 目标发声时长”，之后实际看听微调。
- `at`：**音频文件放入时间线的起点**。如果文件还有前导静音，它不等于人物开口时间；应裁掉多余空白，或按变速后的前导静音时长把 `at` 提前。

```bash
cp "$AVATAR_SKILL/../../examples/voice-plan.json" voice-plan.json
# 编辑 audio、at、rate，按自己的画面与声音填写
python3 "$AVATAR_SKILL/scripts/timed_voice.py" \
  main.mp4 voice-plan.json --out main-redub.mp4
```

`timed_voice.py` 执行每句的保音高变速、时间平移和混音，保留视频流、替换原声音轨。**它不自动找嘴唇、生成配音或选择对齐点**；本次样稿所做的时间分析需要在填写计划前完成。音频重叠或超出片尾时会停止，不替你修改计划。

### 4. 重新核对字幕，再制作包装

```bash
ffmpeg -n -i main-redub.mp4 -vn -ac 1 -ar 16000 redub-16k.wav
whisper-cli -m "$WHISPER_MODEL" -f redub-16k.wav -l zh \
  -oj -osrt -of redub-asr
```

依据新声音更新并复核 `tl.json`，保留确认稿文字。不要把 `redub-asr.json` 直接当成 `tl.json`，两者结构不同；也不要直接复用原声生成的旧字幕时点。`align.py` 读取的是 `cut/` 内的识别缓存，不会因为换了成片音轨就自动改用新声音。本次的字幕还结合短语锚点进行了调整。

复核后以 `main-redub.mp4` 和更新后的 `tl.json` 创建可编辑工程，按[命令指南第 5 步](usage.md#5-创建可编辑工程并渲染)加入字幕、可选贴纸与音乐，输出新的 MP4。原配音、人物、字幕和接点分别检查；解码成功或 Whisper 分数不能代替实际看听。
